# ベンチマークノート：Smart Rabbit（自動発注）からの学び

> 出典：Smart Rabbit（株式会社システムサポート）飲食店向け発注支援システム 提案資料（18p, 2025）。
> 位置づけ：**参考メモ**。要件への正式反映は未承認（v0.5 候補）。「レシピ機能が必要では？」の検討材料。

## Smart Rabbit の核心：レシピ分解（材料BOM）を必須にしない
- 競合のAI自動発注は「メニュー→材料」の**レシピ分解**が必須＝新メニュー/改定のたびにメンテ、専門部署が要る。
- Smart Rabbit は **「単位売上」係数1個**で消費量を推定し、レシピ分解を不要にした：
  - 月間消費量 ＝ 仕入量 − 棚卸在庫（例 1000−100=900個/月）
  - 単位売上 ＝ 月間売上 ÷ 消費量（例 540万÷900＝**6,000円/個**）
  - 当日消費 ＝ 当日売上 ÷ 単位売上（21万÷6,000＝35個）
  - **週次/月次で自動補正**（直近4週/4ヶ月）→ 季節変動を吸収。新メニューは平均値を入れるだけ。

## PrepFlow への移植ヒント（重要順）
1. **レシピは必須にしない。** 仕込みアイテムは「1人前の出来上がり量」だけ持てばよい。材料リスト（旧L2）は**MVP不要**＝後ろ倒し。
2. **FR-09 を「自己補正レシピ」に格上げ。** per-cover 出力を「作った量／余った量」の実績で自動補正＝レシピが自分で育つ。
   - PrepFlow は**予約という確定情報起点**なので、Smart Rabbit の売上統計推定（遅行）より**正確・先行**。
3. **アイテム別 自動/手動・スケール則フラグ**：`per_cover / 1人前×人数 / 固定バッチ`。基本は自動、イレギュラーは手動上書き。
4. **重要項目だけ表示・係数はワンクリック展開**（歩留り/係数は普段隠す）＝ミニマル設計の裏付け。
5. **導入はシミュレーションから**：実際の仕込み量 vs PrepFlow推奨量を数週間並走し差を提示 → P0パイロットに追加すべき握り方。
6. **仕入/発注は自作せず連携**：Smart Rabbit 自身が BtoBプラットフォーム受発注（インフォマート）と連携。PrepFlow の仕入・在庫は **Smart Rabbit / BtoB と連携**でよい（Smart Rabbit は“発注”、PrepFlow は“仕込み生産”＝**補完・提携候補**）。

## 丸呑みできない差（PrepFlow固有で残すもの）
- 単位売上トリックは「合計消費量」を出すだけ＝**共有半製品の合算**（煮切りを複数皿で使う→1タスクに集約）は解決しない。→ **サブレシピ参照（L1の軽いリンク）は任意で残す**（必須ではない）。
- Smart Rabbit は**発注（購買）**、PrepFlow は**仕込み（生産スケジュール）**。目的が違うので係数の使い所は「数量の当て方」に限定して移植する。
